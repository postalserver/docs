---
title: Auto-Responders & Bounces
description: 'How Postal handles bounce messages and auto-responses to mail you have sent.'
---
When you send an e-mail you may be automatically sent a bounce message or an auto responder by the destination mail server. These are handled slightly differently to normal incoming e-mail and it's worth understanding how these work.

## The return path

Messages like these aren't usually sent to the e-mail address that sent the message but are sent to the **return path** address, which Postal uses as the SMTP `MAIL FROM` (envelope sender) for every message it sends. The return path address is `{server-token}@{return-path-domain}`, where the domain is either:

* your installation's return path domain (`dns.return_path_domain`, for example `rp.postal.example.com`), or
* the custom return path for your sending domain (`psrp.yourdomain.com` by default) if you have set up the return path CNAME record and Postal's DNS check for it has passed. Using a custom return path means the envelope sender is on your own domain, which helps with SPF alignment for DMARC. See [Sending domains](/features/sending-domains).

Any mail arriving at the SMTP server for the return path domain, or for any domain beginning with the custom return path prefix, is matched to the mail server by the token in the local part. Mail with an unknown token is rejected with `550 Invalid server token`.

## How bounces are detected

When a message arrives at the return path, Postal looks for `X-Postal-MsgID` headers in the content of the incoming message. Postal adds this header (containing the message's token) to every outgoing message, and most mail servers include the original headers in their bounce reports.

* If one or more original messages are found, the incoming message is recorded as a bounce for each of them. The original message's status is changed to **Bounced**, the bounce is linked to it in the web interface and a [`MessageBounced` webhook](/developer/webhooks#message-bounces) is triggered. The bounce itself is marked as **Processed** and is not delivered anywhere else.
* If no original message can be identified and you have no return path route (see below), the incoming message is marked as failed with the details "This message was a bounce but we couldn't link it with any outgoing message and there was no route for it."

Bounces do **not** automatically add the recipient to the server's [suppression list](/features/mail-server-settings#suppression-list); that only happens on repeated delivery failures when Postal is sending.

## Return path routes

If you wish to route mail which is sent to your return path address (auto-responders, out-of-office replies and anything else that isn't recognised as a bounce) to your application, you can set up a **return path route**. This is the same as a normal route except you should enter the name as `__returnpath__` and leave the domain field blank. You can only choose HTTP endpoints for this type of route. Once added, messages sent to your return path that aren't detected as bounces will be sent to the HTTP endpoint you choose. Messages that *are* detected as bounces are still handled as described above and are not sent to the route.

## Bounces that Postal sends

Postal will itself generate a bounce message back to the sender of an **incoming** message when that message cannot be delivered to its route's endpoint (for example an HTTP endpoint returned a `4xx` status, or the maximum number of delivery attempts was reached), or when the route is set to **Bounce**. The bounce is sent from `Mail Delivery Service <route address>` with the subject `Mail Delivery Failed (original subject)`, the original message attached, and a contact address which is the server's **Postmaster address** setting (or `postmaster@yourdomain.com` if not set). No bounce is generated if the incoming message was itself a bounce or had an empty `MAIL FROM`.

For **outgoing** messages that fail, Postal does not send you a bounce e-mail. Use the `MessageDeliveryFailed` webhook, or check the message in the web interface, instead.
