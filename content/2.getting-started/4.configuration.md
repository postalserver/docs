Postal can be configured through its configuration file, environment variables, or a mixture of both. There are a fair number of areas which can be configured.

* The [configuration reference](/getting-started/configuration-reference) lists every option along with its default, description and environment variable name.
* The same information is available in the Postal repository: the [full example configuration file](https://github.com/postalserver/postal/blob/main/doc/config/yaml.yml) and the [list of environment variables](https://github.com/postalserver/postal/blob/main/doc/config/environment-variables.md).

::callout
Note: If you change any configuration, you should be sure to restart Postal (<code>postal restart</code>). Configuration is read once when each process starts.
::

## The configuration file

Postal looks for its configuration file at the path given by the `POSTAL_CONFIG_FILE_PATH` environment variable. In the container image this is set to `/config/postal.yml`, and the standard installation mounts `/opt/postal/config` on the host at `/config`, so the file lives at `/opt/postal/config/postal.yml` on the host.

The file is YAML, grouped into sections, and **must** include `version: 2` at the top level.

```yaml
version: 2

postal:
  web_hostname: postal.example.com
  web_protocol: https
  smtp_hostname: postal.example.com

main_db:
  host: 127.0.0.1
  username: postal
  password: secret
  database: postal

message_db:
  host: 127.0.0.1
  username: postal
  password: secret
  database_name_prefix: postal
```

Any option that is not present takes its default value. If no configuration file exists at all, Postal will log `No configuration file found` and use environment variables only.

### Paths and `$config-file-root`

Options which refer to files (`postal.signing_key_path`, `smtp_server.tls_certificate_path` and `smtp_server.tls_private_key_path`) default to `$config-file-root/...`. The `$config-file-root` placeholder is replaced with the directory containing the configuration file - `/config` in the standard installation. You can use the placeholder in your own values too.

Remember that paths are evaluated *inside* the container, so a file at `/opt/postal/config/smtp.cert` on the host is `/config/smtp.cert` (or `$config-file-root/smtp.cert`) to Postal.

## Environment variables

All configuration options can also be set by environment variables. Values from environment variables take precedence over values in the configuration file, so you can keep a base `postal.yml` and override individual values per process.

The variable name is the section and option name, upper-cased and joined with an underscore. For example:

| Option | Environment variable |
|---|---|
| `postal.web_hostname` | `POSTAL_WEB_HOSTNAME` |
| `main_db.host` | `MAIN_DB_HOST` |
| `smtp_server.default_port` | `SMTP_SERVER_DEFAULT_PORT` |
| `oidc.enabled` | `OIDC_ENABLED` |

Array options (`postal.smtp_relays`, `postal.trusted_proxies`, `postal.allowed_request_destinations`, `dns.mx_records`, `oidc.scopes`) are given as a comma-separated string, for example `DNS_MX_RECORDS=mx1.postal.example.com,mx2.postal.example.com`.

Postal also loads a `.env` file from the application directory if one exists, which is mainly useful in development.

### Process-specific variables

A few environment variables are not part of the configuration schema but affect individual processes:

| Variable | Description |
|---|---|
| `PORT` | Overrides `web_server.default_port` / `smtp_server.default_port` for this process. |
| `BIND_ADDRESS` | Overrides `web_server.default_bind_address` / `smtp_server.default_bind_address` for this process. |
| `HEALTH_SERVER_PORT` | Overrides the [health server](/features/health-metrics) port for this worker or SMTP server process. |
| `HEALTH_SERVER_BIND_ADDRESS` | Overrides the health server bind address for this process. |
| `POSTAL_CONFIG_FILE_PATH` | The location of the configuration file (default `/config/postal.yml` in the container). |
| `SILENCE_POSTAL_CONFIG_MESSAGES` | Set to `true` to suppress the "Loading config from ..." messages printed to STDERR on start up. |
| `WAIT_FOR_TARGETS` / `WAIT_FOR_TIMEOUT` | Used by the container entrypoint to wait for other services. See [Our container image](/other/containers#waiting-for-services). |

## Ports and bind addresses

The web & SMTP servers listen on ports and addresses. The defaults for these can be set through configuration however, if you're running multiple instances of these on a single host you will need to specify different ports for each one using the `PORT` and `BIND_ADDRESS` environment variables described above.

By default the web server binds to `127.0.0.1:5000` (it is expected to sit behind a web proxy) and the SMTP server binds to `[::]:25` (all IPv4 and IPv6 addresses).

## SMTP relays

By default Postal delivers outgoing mail directly to the recipient's mail servers by looking up their MX records. If you'd rather send everything through one or more relays (a smart host), list them in `postal.smtp_relays`. When any relays are configured, **all** outgoing mail is sent to them and MX lookups are skipped. Each relay is a URL in the form `smtp://host:port?ssl_mode=MODE`:

```yaml
postal:
  smtp_relays:
    - smtp://relay1.example.com:25?ssl_mode=Auto
    - smtp://relay2.example.com:587?ssl_mode=TLS
```

The port defaults to `25` and `ssl_mode` defaults to `Auto`. The available modes are:

* `Auto` - use STARTTLS if the relay offers it, without verifying the certificate. Falls back to plain text if the TLS handshake fails.
* `STARTLS` (note the spelling, which matches the source code) - require STARTTLS and verify the relay's certificate.
* `TLS` - connect using implicit TLS (for example on port 465) and verify the certificate.
* `None` - never use TLS.

## Trusted proxies

The web server determines the client IP address (used for open/click tracking and webhooks) from `X-Forwarded-For` headers set by your web proxy. Only proxies on loopback addresses (`127.0.0.1`, `::1`) and IPv6 unique-local addresses (`fd00::/8`) are trusted by default - private IPv4 ranges such as `10.0.0.0/8` are **not**. If your web proxy runs on another host, add its address or network to `postal.trusted_proxies`:

```yaml
postal:
  trusted_proxies:
    - 10.0.0.5
```

## Legacy configuration

The current version for the Postal configuration file is `2`. This is shown by the `version: 2` in the configuration file itself.

Postal still supports the version 1 (or legacy) configuration format from Postal v2 and earlier - any file without a `version` key is treated as version 1. If you are using this format, you will receive a warning in the logs when starting Postal. We recommend changing your configuration to follow the new v2 format which is documented above, as options added in Postal v3 (such as `worker.*`, `oidc.*`, `migration_waiter.*`, `postal.trusted_proxies` and `postal.allowed_request_destinations`) cannot be set in the v1 format.

The key differences between v1 and v2 configuration are shown below. Options not listed keep the same name in both formats.

| v1 (legacy) | v2 |
|---|---|
| `web.host` | `postal.web_hostname` |
| `web.protocol` | `postal.web_protocol` |
| `dns.smtp_server_hostname` | `postal.smtp_hostname` |
| `dns.return_path` | `dns.return_path_domain` |
| `general.use_ip_pools` | `postal.use_ip_pools` |
| `general.exception_url` | `logging.sentry_dsn` |
| `general.maximum_delivery_attempts` | `postal.default_maximum_delivery_attempts` |
| `general.maximum_hold_expiry_days` | `postal.default_maximum_hold_expiry_days` |
| `general.suppression_list_removal_delay` | `postal.default_suppression_list_automatic_removal_days` |
| `general.use_local_ns_for_domains` | `postal.use_local_ns_for_domain_verification` |
| `general.default_spam_threshold` | `postal.default_spam_threshold` |
| `general.default_spam_failure_threshold` | `postal.default_spam_failure_threshold` |
| `general.use_resent_sender_header` | `postal.use_resent_sender_header` |
| `smtp_relays` (array of `{hostname, port, ssl_mode}`) | `postal.smtp_relays` (array of `smtp://host:port?ssl_mode=mode` strings) |
| `web_server.port` | `web_server.default_port` |
| `web_server.bind_address` | `web_server.default_bind_address` |
| `smtp_server.port` | `smtp_server.default_port` |
| `smtp_server.bind_address` | `smtp_server.default_bind_address` |
| `smtp_server.log_connect` | `smtp_server.log_connections` |
| `message_db.prefix` | `message_db.database_name_prefix` |
| `logging.rails_log` | `logging.rails_log_enabled` |
| `logging.graylog.host` / `port` / `facility` | `gelf.host` / `port` / `facility` |
