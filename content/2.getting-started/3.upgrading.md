If you're not currently running Postal v2 or v3, you'll need to follow the [Upgrading to v2](/getting-started/upgrade-to-v2) documentation before you can use these instructions. If you are upgrading from v2 to v3, also read the [Upgrading to v3](/getting-started/upgrade-to-v3) notes.
::

Once you have installed Postal, you can upgrade it by running this command. This will always upgrade you to the latest version of Postal that has been released.

```bash
postal upgrade
```

This will do a few things in the following order:

* Fetch the latest copy of the installation helpers repository using `git pull` (and re-run itself from the updated copy).
* Look up the latest release of Postal from GitHub and regenerate `docker-compose.yml` for that version (a backup of the previous file is kept as `docker-compose.backup.yml`).
* Pull the new Postal container image.
* Run `postal upgrade` inside a temporary container to perform any necessary updates to the database schema (both the main database and every mail server's message database).
* Restart all running containers (`docker compose up -d --remove-orphans`).

This is not a zero downtime upgrade so it is recommended to do this at a time when traffic will be low and you have scheduled the maintenance as appropriate. If you need zero downtime upgrades, you will need to look for alternative container orchestration systems that can handle this (such as Kubernetes) and use the `migration_waiter` configuration described on the [container page](/other/containers).

The upgrade command needs `curl` and `jq` to be installed in order to determine the latest version.

## Changing to a specific version

By default, running `postal upgrade` will install the latest version available from the Postal container registry. If you need to change the version of Postal to a specific version, you can specify a version for the `postal upgrade` command as follows:

```bash
postal upgrade 3.3.7
```

You can see the available versions in the [CHANGELOG](https://github.com/postalserver/postal/blob/main/CHANGELOG.md).

## Checking the installed version

The version of Postal that is running is shown in the footer of every page in the web interface. You can also run:

```bash
postal version
```

## Rolling back

If you need to return to the previous version, `postal upgrade [previous-version]` will switch the container image back. Note that database migrations are not reversed automatically, so only roll back to a version whose schema is compatible with the migrations that have already run.
