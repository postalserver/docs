Once you've completed all the prerequisites, you can go ahead and start to install Postal.

## Configuration

Before you can start Postal, you'll need some configuration. The repository you cloned includes a tool to automatically generate some initial configuration files.

The hostname used by the Postal installation is separate from the domains that Postal will send mail for. In these examples, we'll use `postal.example.com` as the Postal hostname, matching the example used by the default Postal configuration. You may use another stable hostname, such as `mail.example.com`, but `postal.example.com` remains the canonical documentation example. Keep the roles separate: changing the Postal hostname does not change the sending domain or any domain-derived DNS records.

::callout{icon="i-heroicons-exclamation-triangle" color="amber"}
**Important:** The `postal` label in `postal.example.com` is only part of the example hostname. It is not a reference to `dns.dkim_identifier`, `dns.domain_verify_prefix`, or `dns.custom_return_path_prefix`. Those configuration values have separate meanings and must not be inferred from the hostname.
::

Run the command below and replace `postal.example.com` with the actual hostname you want to access your Postal web interface at. Make sure you have set up this hostname with your DNS provider before continuing.

```bash
postal bootstrap postal.example.com
```

This will generate three files in `/opt/postal/config`.
* `postal.yml` is the main postal configuration file
* `signing.key` is the private key used to sign various things in Postal
* `Caddyfile` is the configuration for the Caddy webserver

Once generated, open `/opt/postal/config/postal.yml` and set the values appropriate for your installation, including database credentials and other deployment-specific settings.

::callout{icon="i-heroicons-information-circle"}
Note that the Docker setup mounts <code>/opt/postal/config</code> as <code>/config</code> so any full directory paths mentioned in <code>postal.yml</code> will likely need to start with <code>/config</code> and not <code>/opt/postal/config</code>.
::

## Configuration file reference

Postal 3.x uses a version 2 YAML configuration file, normally stored at `/opt/postal/config/postal.yml`. The complete configuration schema is maintained in the Postal source repository at [`doc/config/yaml.yml`](https://github.com/postalserver/postal/blob/main/doc/config/yaml.yml). Environment variables are also supported for the same configuration options. If you change the configuration, restart Postal before expecting the new values to be used. See the [configuration reference](https://docs.postalserver.io/getting-started/configuration/) for the generated/default configuration details.
The sections below mirror every top-level section and parameter currently present in `doc/config/yaml.yml`. The source file remains the authoritative reference for defaults and comments; this section explains the operational role of each parameter and highlights values that are commonly changed during deployment. The corresponding environment-variable names are documented separately in [`doc/config/environment-variables.md`](https://github.com/postalserver/postal/blob/main/doc/config/environment-variables.md). The current Postal 3.x configuration uses YAML only; do not look for a TOML equivalent. Keep this reference synchronized with the source configuration file when upgrading Postal.
::callout{icon="i-heroicons-information-circle"}
**Naming rule:** `postal.example.com` is the canonical Postal hostname used in this documentation. You may choose another hostname, such as `mail.example.com`, but do not infer the meanings of `dkim_identifier`, `domain_verify_prefix`, or `custom_return_path_prefix` from the word `postal` in the hostname. These settings control separate DNS behavior.
::

::callout{icon="i-heroicons-exclamation-triangle" color="amber"}
**Configuration safety:** Treat Postal hostnames and DNS prefixes as part of the configuration contract. `postal.example.com` is only the canonical example hostname; `spf.postal.example.com`, `rp.postal.example.com`, `routes.postal.example.com`, and `track.postal.example.com` are separate values configured independently. Likewise, `dkim_identifier`, `domain_verify_prefix`, and `custom_return_path_prefix` are not derived from the hostname. Do not move DNS records to a different level or rename these values simply because another name looks cleaner. Make such changes only as a coordinated DNS and configuration migration.
::

## Initializing the database

Once you've added your configuration, you need to initialize your database by adding all the appropriate tables. Run the following commands to create the schema and then create your first admin user.

```bash
postal initialize
postal make-user
```

## Running Postal

You're now ready to actually run Postal itself. You can go ahead and do this by running:

```bash
postal start
```

This will run a number of containers on your machine. You can use `postal status` to see details of these components.

## Caddy

To handle SSL termination and all web traffic, you'll need to configure a web proxy. You can use anything that takes your fancy here - nginx, Apache, HAProxy, anything - but in this example, we're going to use [Caddy](https://caddyserver.com). It's a great little server that requires very little configuration and is very easy to set up.

```
docker run -d \
   --name postal-caddy \
   --restart always \
   --network host \
   -v /opt/postal/config/Caddyfile:/etc/caddy/Caddyfile \
   -v /opt/postal/caddy-data:/data \
   caddy
```

Once this has started, Caddy will issue an SSL certificate for your domain and you'll be able to immediately access the Postal web interface and login with the user you created in one of the previous steps.

## Next steps

Once you can log in:

1. Create an organization and a mail server.
2. Add the domain you want to send from and follow the [Sending domains](/features/sending-domains) page to verify it and publish its SPF, DKIM and return path records.
3. Create an **SMTP** or **API** [credential](/features/smtp-authentication) and send a test message.

The full set of commands provided by the `postal` helper is documented on [The postal command](/getting-started/postal-command) page.

## Postal's own e-mails

Separately from the mail it delivers for you, Postal sends a small number of e-mails of its own - password resets, send limit warnings and suspension notices. These are sent using the `smtp` section of `postal.yml`, not through one of your mail servers. Once you have a working mail server and credential you can point this section at it (or at any other SMTP server you have access to), then run `postal restart`. `postal test-app-smtp you@example.com` sends a test message using these settings.
